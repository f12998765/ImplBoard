# 表单看板（简道云 · 只读）

一个本地看板，回答两件事：

- 今天哪些**表单被改过**（`entry.updateTime` 落在今天），改了多久、多少字段；
- 今天哪些**表单有人提交数据**，各新增多少条、占全量多少。

外加：按分组列全部表单、近 7 日新增趋势、今日更新时段分布、应用包切换、CSV 导出。所有请求都是读接口，不写任何数据。

## 启动

```bash
cd jdy-today
python3 jdy_today_server.py          # 默认 8787，只监听 127.0.0.1
open http://127.0.0.1:8787
```

首次打开页面会要求粘贴一次 cURL（浏览器里的 Cookie 是 HttpOnly，页面读不到）：

> 已登录的简道云页面 → F12 → Network → 任选一个 `POST`（`menu`、`data/find` 都行）→ 右键 → Copy → **Copy as cURL (bash)** → 粘进页面输入框 → 连接。

服务端会立刻用它验证一次，通过后保存成一份**凭据档案**（`jdy_auth.json`，权限 600，已 gitignore），下次启动免粘贴；凭据过期就再粘一次。

### 多份凭据：添加 / 切换 / 删除

右上角「账号」打开管理弹窗：

- 已存的凭据逐条列出：名字、环境（**飞书** / **简道云**）、域名、appId 前 10 位、是否使用中；
- 「切换」立刻换成那份 Cookie 并重新拉数据；
- 「删除」移除该档案（删的是当前使用中的，会退回未登录状态）；
- 下面粘一份新 cURL + 起个名字 → 「保存并切换」。

**飞书对接环境和普通简道云不是同一个域名**：飞书是 `lark.jiandaoyun.com`，普通是 `www.jiandaoyun.com`，私有部署是你自己的域名。粘贴时地址栏/curl 里的域名会被自动识别并存进档案，`lark.*` 会标成「飞书」，所以两个环境可以各存一份来回切；同一个环境不同账号也可以存多份，用名字区分。

也可以在命令行直接给：

```bash
python3 jdy_today_server.py --curl curl.txt
python3 jdy_today_server.py --cookie "..." --csrf "..." --app-id 6ab0c3281a10a54713c6abf5
```

> 页面必须通过 `http://127.0.0.1:8787` 打开。直接双击 HTML 会因为 HttpOnly Cookie + 跨域限制拿不到数据（页面会给出提示）。

## 页面结构

| 区块 | 内容 |
| --- | --- |
| 顶部 | 账号（凭据管理）、日期选择（可看任意一天，默认今天）、应用包下拉、导出、刷新（没有自动刷新，只在手动点击/改日期/换应用时查询） |
| 指标 | 表单数 / 当日有更新 / 当日有新增 / 当日新增条数（含全部记录数）；选今天时文案是「今日」 |
| 图表 | 近 7 日新增记录柱状图（窗口以所选日期结尾）、当日更新时段 24 小时分布 |
| 当日更新的表单 | 表单、分组、最后更新、距现在、字段数 |
| 当日有数据添加 | 表单、新增、总条数、占比条 |
| 全部表单 · 按分组 | 分组汇总行（可折叠）+ 表单、最后更新、距现在、字段数、总条数、新增 |

## 接口与口径

| 用途 | 接口 | 次数 |
| --- | --- | --- |
| 应用列表 | `POST /dashboard/apps` `{"has_app_group":true}` | 1 |
| 应用树 | `POST /dashboard/api_doc/list_entry` `{"appId":…}` → `menu` + `entryMap` | 1 |
| 表单详情 | `POST /_/admin/app/{appId}/form/{formId}` → `entry.updateTime`、`content.items` | 每表 1 |
| 记录数 | `POST /_/data_process/admin/data/count`（无 filter = 全部；`createTime ≥ 当日` 即当日新增） | 每表 2（选往日 3） |

实测：84 张表单 = 252 个请求，16 并发约 12 秒（再往上加并发不再变快，服务端在 ~13 req/s 附近就压住了）。所以页面加了进度卡，边查边显示：

```
正在查询
已查询 32 / 84 张表单 · 38% · 2s
正在读：人员信息表 · 新增、客户信用额度 · 总数、物料信息表 · 结构 等 8 张
共 84 张表单，每张 1 次结构 + 2–3 次计数（并发 16）。

查询日志
01:00:30  表单 30/84
01:00:31  表单 40/84
01:00:32  开始统计近 7 日新增（43 张有数据的表单，每张 8 次计数）
```

进度分两个阶段：`forms`（读结构 + 计数）→ `trend`（近 7 日趋势，只查总条数 > 0 的表单）→ `done`；趋势也在这张卡里跑完，不另开请求。`current` 里带「表单名 · 结构/总数/新增/趋势」，慢请求超过 8 秒会在行尾提示「Ns 没有新进展」，日志里每 10 张表记一行，最多留 40 行。

> 某一天的新增条数用「`gte 当日` 减 `gte 次日`」算：`data/count` 的 `lt` 条件实测不生效（传了会返回 0），只能用两次 `gte` 相减。选今天时省掉第二次。

- 时区：服务端返回 UTC（`...Z`），统一转 Asia/Shanghai 再判断「今天」；count 的 filter 字符串本身按北京时间解释。
- 一次全量：`表单数 × 3` 个请求（详情 / 总数 / 今日数），默认 16 并发（`--workers`），报告缓存 60 秒（按 appId + 日期），`&fresh=1` 强制重算；趋势图只查「总条数 > 0」的表单（本例 43 张 × 8 个边界，约 6 秒），缓存 15 分钟。同一天只允许一个查询在跑（单飞锁），避免两个请求把进度和日志搅在一起。
- 时段分布图按 `updateTime` 的小时归桶，柱子上直接标张数（`0` 不标），右上角是当日有更新的表单数。
- `updateTime` 是**表单条目级**时间：改名、换图标、改提交提示也会刷新。结构变了它一定变，它变了不一定结构变。

## 本地接口

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/status` | 是否已认证、当前档案、档案数量 |
| GET | `/api/auth` | 档案列表（不含 Cookie/CSRF，只给名字、域名、环境、appId） |
| POST | `/api/auth` | 粘贴 cURL（或 cookie+csrf+host+appId）新增/更新一份档案并切换过去 |
| POST | `/api/auth/switch` | `{"id":"p…"}` 切换档案，会先验证一次 |
| POST | `/api/auth/delete` | `{"id":"p…"}` 删除档案 |
| GET | `/api/apps` | 应用包列表（缓存 10 分钟） |
| GET | `/api/report?appId=&date=&fresh=` | 某天的汇总，含 `trend`（缓存 60 秒，按 appId+日期；`fresh=1` 重算） |
| GET | `/api/trend?appId=&date=&only=` | 单独取 7 日趋势（缓存 15 分钟，页面已不用） |
| GET | `/api/progress?appId=&date=` | 当前查询进度：`phase/done/total/current[]/logs[]` |

## 文件

| 文件 | 说明 |
| --- | --- |
| `index.html` | 页面（无 CDN、无快照，数据全部来自本地服务） |
| `jdy_today_server.py` | 本地只读代理 + 静态服务，仅标准库 |
| `jdy_auth.json` | 凭据档案（`{active, profiles[]}`），每个 profile 一份 Cookie，权限 600，已 gitignore |

## 参数

```
--curl PATH       从 cURL 文件读取凭据
--cookie STR      直接给 Cookie
--csrf STR        x-csrf-token
--app-id ID       默认应用 ID
--host HOST       域名（可带 http(s)://）
--scheme http|https
--port N          默认 8787，只监听 127.0.0.1
--workers N       并发数，默认 16
```
